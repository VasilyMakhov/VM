# VM² — учебный маркетплейс на Flask и Firebird

**VM² (VasilyMakhov)** — проект, выполненный в рамках курсовой работы. Это маркетплейс, в котором есть три роли: **покупатель**, **продавец** и **модератор**. Покупатель выбирает товары, складывает их в корзину и оформляет заказ; продавец управляет своими товарами и остатками на складах, подтверждает оплату и передаёт товар в доставку; модератор ведёт справочники категорий и складов.

Проект показывает полный цикл работы с реляционной базой данных: проектирование схемы, SQL-запросы, транзакции, обработку статусов заказа и разграничение прав доступа.

## Возможности

### Гость

- просмотр главной страницы;
- просмотр каталога товаров;

- просмотр карточки товара;

- добавление товаров в избранное и удаление из него;

- просмотр истории заказов;
- подтверждение получения заказа.

### Продавец

- просмотр списка своих товаров;
- создание товара с загрузкой изображения;
- указание остатков товара на разных складах;
- редактирование товара и его остатков;
- удаление товара;
- просмотр заказов, в которых есть его товары;
- подтверждение оплаты своей части заказа;
- отметка о передаче товаров в доставку.

- просмотр списка складов;
- добавление, редактирование и удаление складов.

## Архитектура

Приложение построено на **blueprint-ах Flask**. Каждый blueprint отвечает за свою предметную область:

| Blueprint | Файл | Ответственность |
|---|---|---|
| `main` | `routes/main.py` | главная страница и личный кабинет |
| `auth` | `routes/auth.py` | вход, регистрация, выход, редактирование профиля |
| `catalog` | `routes/catalog.py` | каталог, карточка товара, товары продавца, заказы продавца |
| `cart` | `routes/cart.py` | корзина и выбор товаров |
| `orders` | `routes/orders.py` | оформление заказа, оплата, история заказов |
| `favorites` | `routes/favorites.py` | избранное |
| `moderator` | `routes/moderator.py` | панель модератора: категории и склады |

Схема обработки запроса:

```text
Браузер
   │ HTTP-запрос
   ▼
app.py (Flask)
   │ выбор blueprint по URL
   ▼
routes/*.py
   │ SQL-запросы через firebird-driver
   ▼
Firebird 5.1 (/db/wb_vasa.fdb)
   │ результат запроса
   ▼
templates/*.html (Jinja2)
   │ готовый HTML
   ▼
Браузер
```

Подробное описание архитектуры, бизнес-логики и модели данных — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Быстрый старт

### 1. Требования

- Python 3.11+;
- Firebird 5.x (сервер или embedded-режим);
- клиент `isql-fb` (нужен для развёртывания БД из SQL-скриптов);
- доступ к каталогу, где будет лежать файл базы `.fdb`.

### 2. Клонирование и виртуальное окружение

```bash
git clone <адрес-репозитория> VM
cd VM

python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### 3. Настройка подключения к БД

Параметры подключения находятся в `db.py`:

```python
from firebird.driver import connect

def get_connection():
    return connect(
        database="/db/wb_vasa.fdb",
        user="SYSDBA",
        password="masterkey",
    )
```

Измените путь, пользователя и пароль под своё окружение.

### 4. Развёртывание базы данных

Рекомендуемый способ — готовый скрипт:

```bash
chmod +x scripts/init_db.sh
./scripts/init_db.sh /db/wb_vasa.fdb
```

Скрипт создаст базу, применит схему и загрузит тестовые данные.

Если база уже существует и её нужно пересоздать, скрипт спросит подтверждение. **Внимание:** существующий файл `.fdb` будет удалён.

Ручной способ:

```bash
# 1. Создать пустую базу
isql-fb -q -u SYSDBA -p masterkey -i sql/00_create_database.sql

# 2. Создать таблицы, ключи и триггеры
isql-fb -q -ch UTF8 -u SYSDBA -p masterkey /db/wb_vasa.fdb -i sql/01_schema.sql

# 3. Загрузить тестовые данные
isql-fb -q -ch UTF8 -u SYSDBA -p masterkey /db/wb_vasa.fdb -i sql/02_seed.sql
```

Если путь к базе отличается, отредактируйте его в `sql/00_create_database.sql` и в `db.py`.

### 5. Запуск приложения

```bash
python app.py
```

Приложение будет доступно по адресу:

```text
http://127.0.0.1:2911
```

## Основные сценарии

### Покупатель

1. Зарегистрироваться или войти.
2. Открыть каталог, отфильтровать товары.
3. Открыть карточку товара и добавить его в корзину или избранное.
4. В корзине отметить нужные товары и нажать «Оформить заказ».
5. Указать адрес доставки и способ оплаты.
6. Если выбрано СБП — перейти на страницу оплаты и нажать «Я оплатил, честно».
7. Дождаться подтверждения оплаты продавцом.
8. После передачи заказа в доставку подтвердить получение в «Мои заказы».

### Продавец

1. Войти под аккаунтом продавца.
2. Открыть «Мои товары» → «Добавить новый товар».
3. Заполнить название, категорию, описание, цену, загрузить изображение.
4. Указать количество товара на каждом складе.
5. В разделе «Заказы с товарами» увидеть заказы, в которых есть его товары.
6. Подтвердить оплату своей части заказа (для СБП).
7. Отметить передачу товаров в доставку.

### Модератор

1. Войти под аккаунтом модератора.
2. Открыть «Панель модератора».
3. Управлять категориями и складами.

## Статусы заказа

В базе используются отдельные справочники статусов.

### Статус заказа (`ORDER_STATUSES`)

| ID | Название | Когда используется |
|---|---|---|
| 1 | Новый | заказ создан |
| 2 | Подтверждён | все продавцы подтвердили оплату |
| 3 | Собирается | зарезервировано под будущее развитие |
| 4 | Передан в доставку | все продавцы передали товары |
| 5 | Доставлен | покупатель подтвердил получение |
| 6 | Отменён | зарезервировано под отмену |

### Статус оплаты (`PAYMENT_STATUSES`)

| ID | Название |
|---|---|
| 1 | Ожидает оплаты |
| 2 | Ожидает проверки |
| 3 | Оплачено |
| 4 | Отклонено |

### Статус доставки (`DELIVERY_STATUSES`)

| ID | Название |
|---|---|
| 1 | Не отправлен |
| 2 | В пути |
| 3 | Доставлен |
| 4 | Отменён |

### Флаги продавца (`ORDER_SELLERS`)

| Поле | Значение |
|---|---|
| `PAYMENT_CONFIRMED` | продавец подтвердил оплату своей части заказа |
| `HANDED_TO_DELIVERY` | продавец передал свои товары в доставку |
